# Blast Web App — разбор фронта по экранам

Для маркетингового ревью и поиска мест, где теряются пользователи.
Дата: 2026-07-26. Всё проверено на живом приложении, не по памяти.

Обозначения: **[UX]** — предложение по опыту, **[ВИЗ]** — по визуалу,
**[МЕТРИКА]** — что стоит замерять, **[ДЫРА]** — то, чего сейчас нет вообще.

---

## Карта пути пользователя

```
/register или /login
   → модалка «Подтверди в Telegram»
      → (если ФИО нет) обязательный шаг «Как тебя зовут?»
         → /app (дашборд)
            → модалка «Новый проект»
               → /app/projects/:id (пустой батч)
                  → /app/generate (визард, 5 этапов)
                     → /app/processing/:jobId (рендер)
                        → /app/projects/:id (готовый батч)
                           → /app/projects/:id/post (выкладка в TikTok)
                              → /app/stats (аналитика и итерации)
```

Побочные ветки: `/app/pricing` (тарифы), `/app/profile` (лимиты, оплата, TikTok),
`/app/admin/analytics` (админка), `/legal/*`, 404/error.

## 1. Вход и регистрация

### `/login`
**Что делает.** Заголовок «Вход», подзаголовок, одна кнопка **«Войти через Telegram»**,
пояснение «Подтверждение придёт в Telegram — почта и пароль не нужны», ссылка на регистрацию.
Полей ввода нет вообще.

### `/register`
**Что делает.** То же плюс два обязательных поля — **Имя** и **Фамилия** (валидация на сабмите:
«Укажи имя» / «Укажи фамилию»). Кнопка «Зарегистрироваться» ведёт в бота, ФИО уезжают вместе с токеном.

### Модалка подтверждения в Telegram
**Что делает.** Иконка, заголовок, текст, одна кнопка, которая меняет роль:
«Открыть @blast808bot» → «Проверить» → (через 10 минут) «Запросить новую ссылку».
Параллельно идёт авто-поллинг раз в 2.5 с: как только бот получил `/start`, пользователь
заходит сам, без нажатий.

### Шаг «Как тебя зовут?» (ProfileSetupGate)
**Что делает.** Полноэкранный обязательный шаг, если аккаунт создан без ФИО (вход без формы,
а в Telegram нет имени). Закрыть нельзя.

### Наблюдения

- **[UX] Нет объяснения, зачем Telegram.** Для артиста это неочевидный способ входа. Один из
  главных подозреваемых на отвал первого экрана: человек видит «войти через мессенджер» и
  закрывает. Стоит добавить одну строку выгоды — «Через бота придут уведомления о готовых
  роликах» — то есть Telegram не прихоть, а канал доставки результата.
- **[UX] Регистрация и вход — визуально одинаковые экраны.** Новый пользователь может нажать
  «Войти», уйти в бота, вернуться и попасть на шаг ФИО, хотя он думал, что регистрируется.
  Флоу не ломается, но ощущается как сбой. Можно объединить в один экран «Продолжить через
  Telegram», а ФИО спрашивать всегда после подтверждения — тогда развилки нет вообще.
- **[UX] Пользователь уходит из вкладки в Telegram и может не вернуться.** Сейчас возврат на
  сайт — целиком его инициатива. **[ДЫРА]** Бот после подтверждения не присылает ссылку назад
  в приложение. Одно сообщение «Готово, возвращайся: <ссылка>» закрывает разрыв.
- **[МЕТРИКА] Ключевой разрыв воронки** — `signup_started` → `signup_completed`. Он уже
  трекается. Если там просядет, причина в одном из трёх: непонятно зачем TG, не вернулся из
  бота, не нашёл бота. Стоит различать: добавить событие «нажал Открыть бота» отдельно от
  «отправил форму».
- **[ВИЗ] На `/login` пустая правая колонка** — визуал слева, а справа заголовок, кнопка и
  ссылка. Много воздуха, ощущение незаполненности. Можно занять это место соцдоказательством
  (сколько роликов сгенерировано, примеры).
- **[ДЫРА] Нет ни одного примера результата** до входа. Человек регистрируется вслепую.
  Для маркетинга это, вероятно, самая дорогая потеря: показать 2–3 готовых ролика прямо на
  экране входа дешевле, чем потом объяснять ценность внутри.

## 2. Дашборд `/app`

**Что делает.** Три блока: Hero с приветствием по имени и кнопкой «Создать проект»;
карточка «Все проекты» (последние 2 + переход в раздел); карточка «Статистика».

**Состояния:**
- **Нулевой аккаунт** — фантомные строки проектов (opacity .18) под затемняющей подложкой,
  текст «Пока нет проектов — создай первый» и сплошная фиолетовая кнопка.
- **С проектами** — строки: обложка 80×80, название, статус с цветной точкой, просмотры.
- **Статистика, 3 состояния**: TikTok не подключён → «Подключить»; подключён, мало данных →
  «Собираем данные» + чипы «0 создано / 0 опубликовано / 10 осталось»; данных хватает →
  инсайт-бары.

### Наблюдения

- **[UX] Дашборд не помогает продолжить работу.** Если у человека есть незаконченный визард
  или готовый батч, который он не выложил, дашборд об этом не говорит. Главный экран должен
  начинаться с «где ты остановился»: «Батч на 5 роликов готов — выложить» или «Ты не закончил
  настройку». Сейчас первое действие всегда «создать новый», хотя чаще нужно «доделать старое».
- **[UX] «Создать проект» на пустом аккаунте дублируется дважды** — в Hero и в карточке
  проектов. Не ошибка, но на первом экране это две одинаковые кнопки рядом.
- **[ВИЗ] Просмотры «0» огромным кеглем (48px)** в строке проекта. Пока роликов нет, нули
  доминируют. При нуле лучше показывать «—» или прятать блок.
- **[МЕТРИКА]** Стоит замерять, что нажимают первым на нулевом аккаунте: Hero-кнопку,
  кнопку в карточке или «Подключить TikTok». Это покажет, куда люди реально хотят идти.
- **[ДЫРА] Нет онбординга.** Человек впервые видит приложение и должен сам догадаться:
  создать проект → загрузить трек → пройти 5 этапов. Ни подсказки, ни примера, ни
  «посмотреть, как это работает».

## 3. Проекты `/app/projects`

**Что делает.** Верхняя карточка «Текущий проект» с двумя мини-статами («Сгенерировано N»,
«Сделать ещё ∞»), ниже лента всех проектов + ghost-плитка «Создать проект».

**Состояния:** нет проектов → «Нет активного проекта» + «Создай первый проект»;
есть проекты → карточки со статусами (Активный / В процессе / Завершен).

### Наблюдения

- **[UX] Слово «Текущий проект» и статус «Активный» — разные вещи**, а выглядят одинаково.
  Текущий — тот, в который идёт генерация по умолчанию; ACTIVE — стадия жизненного цикла.
  Мы это развели в коде, но в интерфейсе пользователь видит два похожих термина.
- **[UX] Карточка проекта не показывает главного** — сколько роликов готово и сколько из них
  опубликовано. Сейчас там название, статус и просмотры. Артисту важно «3 из 5 выложены».
- **[ВИЗ] «Сделать ещё ∞»** — символ бесконечности без объяснения выглядит как ошибка.
  Лучше «Без лимита» словами.
- **[ДЫРА] Проект нельзя ни переименовать, ни удалить, ни архивировать.** Ошибся в названии —
  живёшь с ним. Лента со временем зарастёт мусором, и это ударит по возврату в продукт.

## 4. Модалка «Новый проект»

**Что делает.** Заголовок, поле «Назови проект» (фиолетовая обводка при вводе), опциональная
дроп-зона обложки с превью и именем файла, кнопка «Создать проект». Проект сразу становится
текущим, редирект на его страницу.

### Наблюдения

- **[UX] Непонятно, что такое «проект».** Для пользователя это трек. Проект = трек + все
  батчи по нему, но нигде не сказано. Подпись «Проект — это один трек и все ролики по нему»
  снимает вопрос.
- **[UX] Обложка ни на что не влияет** — она не попадает в ролики, это просто картинка
  карточки. Человек может решить, что это обложка видео, и потратить время на подбор.
- **[UX] Название не подставляется из трека.** Логичнее: сначала трек, имя файла → название
  проекта, и поле можно вообще не показывать.

## 5. Страница батча `/app/projects/:id`

**Что делает.** Слева карточка трека (название, псевдоним, метка «Текущий проект» либо кнопка
«Сделать текущим»), пилюли батчей с «+», список генераций; справа колонка превью с листалкой.

**Состояния:** пусто → «Готовых генераций пока нет» + «Создать первый батч»;
есть видео → строки «Видео №N · источник · стиль субтитров · хук», кнопки «Выложить в TikTok»
у каждой и «Выложить все» сверху.

### Наблюдения

- **[UX] Ролики нельзя отличить друг от друга по существу.** Подписи «Ночной город · Brat ·
  Без хука» — это параметры генерации, а не то, чем ролики отличаются визуально.
  **Это ровно то место, где нужен саммари по каждому ролику** (см. раздел 12).
- **[UX] Нет «скачать всё»** одной кнопкой — только по одному.
- **[UX] Непонятно, что уже выложено.** Опубликованный ролик визуально не отличается от
  неопубликованного; «Выложить все» умно пропускает выложенные, но пользователь этого не видит.
- **[ВИЗ] Превью справа занимает половину экрана**, но показывает один ролик. При 5 роликах
  сравнивать неудобно — приходится листать по одному.
- **[МЕТРИКА]** Здесь ключевая точка отвала после генерации: сгенерировал, но не выложил.
  Событие `generation_completed` → `video_posted` уже в воронке, но стоит добавить время
  между ними — если проходят сутки, значит человек ушёл думать и не вернулся.

## 6. Визард `/app/generate` — 5 этапов

Общая рамка: слева карточка с шагами (Трек · Фон · Текст · FX · Пул), справа «Рабочая зона»
с живым превью выбранного. Порядок прохождения: Трек → Фон → Текст → FX → Пул.

### Этап 1 «Трек»
Загрузка MP3/WAV (drag & drop), после загрузки — имя файла, длительность, формат.
Тайминг отрывка «от / до» с маской мм:сс:мс и кнопкой «Прослушать» (играет именно выбранный
отрезок). Справа панель текста: «вставить» из буфера либо ручной ввод, затем выделение
строк припева мышью → «Выбрать фокус-отрывок».

- **[UX] Ограничение длины отрывка (15 с на триале / 30 с на платном) всплывает постфактум** —
  тостом «Отрывок слишком длинный. Тайминг сброшен». Сброс всего ввода за ошибку — грубо;
  лучше подсвечивать лимит заранее и не давать выйти за него.
- **[UX] Вставка текста через кнопку «вставить»** зависит от доступа к буферу; фолбэк на
  ручной ввод есть, но он появляется только после неудачи. Проще сразу показывать поле.
- **[ДЫРА] Нет распознавания текста из аудио.** Человек должен где-то взять текст трека и
  вставить руками. Для продукта «lyric-video на автопилоте» это самое слабое место флоу.

### Этап 2 «Фон»
Три режима: **Футажи** (библиотека с типами: Стандартные / Личности / …, карточки-примеры 4:3),
**Фото** (то же + тумблер «Эффекты» и стили: Ксерокс / Глитч / Неон / Старая камера),
**Цветной** (палитра + строб). Плюс «Загрузить футажи» — свои исходники.
Внизу пилюли выбранного: «Х2 Футажи · Х1 Фото · Х1 Цвет».

- **[ВИЗ] Карточки-примеры зафиксированы 348×261 (ровно 4:3)** — под контент 1920×1440.
- **[UX] «Вариации» и «Х2/Х1» — внутренняя терминология.** Пользователь не знает, что такое
  вариация и почему их 4.
- **[UX] Нельзя посмотреть, как футаж выглядит с его треком** — превью абстрактное.

### Этап 3 «Текст» (субтитры)
Выбор стилей (Brat / Jakson / Impulse / Tape / Trendy), цвет субтитров, превью на реальном
тексте пользователя.

- **[UX] Названия стилей ничего не говорят.** Brat vs Trendy — надо кликать и смотреть.
  Подписи в одно слово («жирные заглавные», «плёночные») ускорят выбор.

### Этап 4 «FX»
Тайминг дропа (3 варианта от AI + свой), 5 типов FX: Звук / Объект / Эффекты / Движение /
Мысль, у каждого — «?»-подсказка и свой набор (Молния, Затвор, Слоу-шаттер, Негатив зум…).

- **[UX] Самый сложный этап.** Пять типов, у каждого своя вкладка и списки — легко потеряться.
  При этом этап **опционален**, но об этом нигде не сказано: «Продолжить» активна всегда.
  Явное «Можно пропустить» снизит тревогу и ускорит первый проход.
- **[UX] «Дроп» — жаргон.** Часть аудитории не поймёт; «самый яркий момент трека» понятнее.

### Этап 5 «Пул»
Распределение: общее число видео (±), сколько роликов на каждый фон, на каждый стиль
субтитров, шрифты для цветного, «Распределить поровну», карусель «Комбинации» с превью
итоговых сочетаний. Кнопка «Сгенерировать».

- **[UX] Самый мощный и самый непонятный экран.** По сути это матрица «фон × субтитры × хук»,
  но подана как набор счётчиков. Новичку тут нечего делать — ему нужен пресет «сделай 5
  разных, я доверяю».
- **[UX] «Комбинации 1/N» — единственное место, где видно, что получится**, но карусель
  маленькая и легко пропускается.
- **[МЕТРИКА]** Стоит замерять время на этапе и число возвратов назад. Если Пул — самый
  долгий этап, значит он и есть барьер перед генерацией.

## 7. Генерация `/app/processing/:jobId`

**Что делает.** Прогресс «N/M видео», «Осталось ~N минут», список готовых по мере рендера,
превью. По завершении — автоматический переход на страницу батча.

**Состояния:** идёт рендер; **не найдено** (ссылка устарела) — «Генерация не найдена» +
«К проектам»; **упало** — «Генерация не удалась» + «Собрать заново» (кредиты возвращаются).

### Наблюдения

- **[UX] Экран ожидания ничем не занят.** 2–7 минут человек смотрит на прогресс-бар. Это
  идеальное место рассказать, что происходит («подбираем футажи под настроение», «расставляем
  субтитры по словам») — и заодно продать ценность продукта.
- **[UX] Нельзя закрыть вкладку спокойно.** Нигде не сказано «можно уйти, пришлём в Telegram».
  А ведь бот уже подключён — это готовый канал возврата.
- **[МЕТРИКА]** Отвал на этом экране (ушёл и не вернулся) — важная цифра. Сейчас
  `generation_completed` есть, но «вернулся ли смотреть» — нет.

## 8. Выкладка в TikTok `/app/projects/:id/post`

**Что делает.** Полноэкранный режим: слева превью ролика с пикером обложки (8 кадров с бэка),
справа форма — описание с хештегами, приватность (Все / Друзья / Только я), тумблеры
комментариев и дуэтов, время публикации, чекбокс прав на музыку, кнопка «Опубликовать».

**Состояния:** черновик (кнопка заблокирована + подсказка «Чтобы опубликовать, добавь:
описание, кто увидит публикацию, согласие на права»); загрузка; опубликовано («Открыть видео»);
переход «к следующему видео».

### Наблюдения

- **[UX] Описание пишется с нуля для каждого ролика.** При 5 роликах это 5 раз писать текст.
  **[ДЫРА]** Нет ни шаблона, ни генерации описания из текста трека, ни «применить ко всем».
  Это прямой тормоз главной ценности — «выложить пачку».
- **[UX] Нет хештег-подсказок**, хотя кнопка «#» есть.
- **[UX] «Время публикации» выглядит как планировщик**, но на деле это поле рядом с кнопкой
  «Опубликовать» — непонятно, отложит ли оно публикацию.
- **[UX] После публикации нет ощущения результата.** «Открыть видео» — и всё. Ни «выложено
  3 из 5», ни прогресса по батчу.
- **[МЕТРИКА]** Тут самый ценный сигнал: сколько роликов из батча реально доходят до TikTok.
  Стоит считать не только `video_posted`, но и «дошёл до экрана постинга и ушёл без публикации».

## 9. Статистика `/app/stats`

**Что делает.** Три метрики (Просмотры / Вовлечение / Опубликовано) с трендами, «Эволюция
контента» — итерации.

**Состояния:** мало данных → «Собираем данные», «0 из 10 видео готовы к анализу», чипы;
данных достаточно → инсайт «В 2.3 раза эффективнее», сравнение «личные исходники (1120
просмотров) vs средний ролик (480)», блок «Настроить итерацию» (фиксируем исходники,
тестируем субтитры, число видео).

### Наблюдения

- **[UX] Порог 10 роликов очень высокий.** На триале доступно 5 — то есть на бесплатном
  тарифе увидеть инсайт **невозможно в принципе**. Человек упирается в «0 из 10» и не
  понимает, что для этого надо платить. Либо снизить порог, либо честно писать «нужен
  платный тариф».
- **[UX] Итерации — сильнейшая идея продукта** (тестируем гипотезы на контенте), но спрятаны
  в конце страницы, которая почти всегда пустая.
- **[МЕТРИКА]** «Дошёл до 10 опубликованных» — фактически метрика активации продукта.
  Сейчас в воронке её нет.

## 10. Профиль `/app/profile`

**Что делает.** Шапка: аватар (свой или из TikTok), имя с фамилией, псевдоним с карандашом,
кнопка TikTok, «Выйти». Карточка «Лимиты» (Треки, Генерации) с прогресс-барами. Карточка
«Тариф» — у бесплатного промо-блок, у платного состав пакета и шкала месяцев с бонусами.
Ниже — карточка «Оплата» (только на платном).

**Состояния оплаты:** активна («Следующее списание — 24 августа»); **оплата не прошла**
(«Списание не удалось — доступ пока сохранён» + «Обновить оплату»); **отменена**
(«Автопродление отключено, доступ до 24 августа» + «Возобновить»). Отмена — с подтверждением.

### Наблюдения

- **[UX] Промо-блок на бесплатном тарифе не показывает цену.** «Расширить доступ» ведёт на
  тарифы, но человек не знает, о каких деньгах речь.
- **[UX] Шкала месяцев с бонусами** («+1 трек к лимиту», «безлимит видео») — интересная
  механика удержания, но она видна только уже оплатившим. На бесплатном о ней не сказано,
  хотя это сильный аргумент к покупке.
- **[UX] Нет истории платежей и чеков.** Для подписки это ожидаемо.
- **[ВИЗ] Прогресс-бар «Генерации ∞»** заполнен на 0% и выглядит сломанным. При безлимите
  шкалу лучше не рисовать.

## 11. Тарифы `/app/pricing`

**Что делает.** Три карточки: Blast (1 990 ₽/мес, 100 видео, до 4 треков, безлимит каждый
3-й месяц), Glow (7 990 ₽, 400 видео, 10 треков, CapCut-шаблон), Impulse (29 990 ₽, безлимит
видео, 24 трека, менеджмент). У каждой — чекбокс согласия с политикой и офертой (реальные
ссылки), кнопка с ценой, по ховеру превращается в «Купить».

### Наблюдения

- **[UX] Цена в кнопке — рискованное решение.** Кнопка выглядит как ярлык, а не как действие;
  «Купить» появляется только на ховере (на мобильном ховера нет вообще).
- **[UX] Не видно, что уже куплено.** Текущий тариф никак не отмечен.
- **[UX] Разница между «Подписка» и «Продукт»** (Blast — подписка, Glow/Impulse — продукт)
  никак не объяснена, хотя это принципиально разные условия оплаты.
- **[UX] Нет годовой опции и нет сравнения тарифов таблицей** — три карточки с разными
  наборами буллетов сложно сопоставить.
- **[МЕТРИКА]** Тут просится замер: дошёл до тарифов → поставил галочку → нажал цену.
  Сейчас событие только на успешную покупку, а отвал на галочке не виден.

## 12. Про саммари по каждому ролику — согласен, это заметная дыра

Сейчас ролик описан как **«Видео №1 · Ночной город · Brat · Без хука»** — это параметры
генерации. Из них пользователь не может понять:

- чем этот ролик отличается от соседнего (если фон и стиль совпали — подписи идентичны);
- какой фрагмент текста в нём звучит;
- почему стоит выложить именно его;
- что сработало, если он собрал просмотры.

**Что предлагаю показывать в саммари ролика** (данные для этого уже есть в `render_job`):

| Блок | Содержание | Откуда берётся |
|---|---|---|
| Строка текста | Какой фрагмент лирики в кадре | `renderJob.lyrics` + тайминг |
| Визуальный ряд | Тип фона + конкретный вайб, есть ли свои исходники | `variation.background` |
| Подача | Стиль субтитров человеческим словом | `variation.subtitle` |
| Акцент | Какой FX и на какой секунде (дроп) | `variation.hook` + `dropTime` |
| Длительность | Секунды | `durationMs` |
| Отличие | «Тот же фон, другие субтитры» — чем отличается от соседей по батчу | сравнение вариаций |
| Результат | Просмотры/вовлечение после публикации | TikTok Display API |

Это же саммари решает три задачи разом: **выбор** (что выложить первым), **обучение**
(человек начинает понимать, из чего состоит его контент) и **аналитику** (после публикации
привязывает цифры к конкретным решениям — и кормит блок «Эволюция контента»).

## Сводка: где вероятнее всего теряем людей

По убыванию моей оценки риска.

1. **Экран входа** — нет ни объяснения Telegram, ни примеров результата. Решение вслепую.
2. **Уход в бота** — человек покидает вкладку, и вернуть его нечем (бот не даёт ссылку назад).
3. **Ввод текста трека вручную** — единственный по-настоящему трудоёмкий шаг, ломает обещание
   автоматизации.
4. **Этап «Пул»** — матрица распределения без пресета для новичка.
5. **После генерации** — ролики неразличимы, непонятно, какой выкладывать (сюда бьёт саммари).
6. **Экран постинга** — описание пишется руками для каждого ролика.
7. **Статистика** — порог 10 роликов недостижим на триале, инсайт не увидеть.
