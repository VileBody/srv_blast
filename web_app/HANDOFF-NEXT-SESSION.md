# Blast Web App — промт для следующей сессии

Ты продолжаешь работу над **Blast Web App**. Прочитай целиком до первого действия.
Рядом лежит `FRONTEND-REVIEW.md` — разбор экранов, из него выросла часть задач.
Раздел 4 прошлого хендоффа закрыт полностью (юр-страницы, анти-фрод, «N из M выложено»,
аналитика ведущих параметров, «текущий/активный», вход vs регистрация, правки визарда,
техдолг) — что осталось и что нужно от владельца, см. §4.

## 1. Что за проект

Веб-приложение для артистов: генерация lyric-video (вертикальные Reels/TikTok) + постинг
в TikTok и аналитика.

**Пути и стек**
- Корень: `C:/Users/Пользователь/Desktop/blast_react_tailwind_fastapi_mock`
- Фронт: `frontend/` — React 18 + Vite + TS + Tailwind 3, react-query, react-router, i18next (ru/en)
- Бэк: `backend/` — FastAPI. Состояние в БД (см. §3), реестр аккаунтов (`app/auth_store.py`),
  аналитика (`app/analytics.py`), TG-бот (`app/telegram_bot.py`), Google-вход (`app/google_auth.py`),
  рендер (`app/render_worker.py`), безопасность (`app/security.py`), персист (`app/persistence.py`)

**Запуск (через preview_start, НЕ через Bash):**
- `preview_start {name: "blast-frontend"}` → 5173
- `preview_start {name: "blast-backend"}` → **8001 обязательно** (на него завязан OAuth-возврат)
- У бэка теперь есть `--reload` с `--reload-dir backend` (раньше reload висел на всей домашней
  папке и перезапускался от чужих файлов). Перезапуск всё равно надёжнее: если правка Python
  «не подхватилась», останови и подними preview заново.

## 2. Жёсткие правила

1. **Секреты.** Не писать значения секретов в файлы, не читать `backend/.env`. Проверять
   конфиг косвенно: `/api/tiktok/status`, `/api/auth/providers`, публичные поля.
   Для тестов интеграций поднимать изолированный экземпляр с фейковыми ключами через
   `TestClient` и `os.environ` — `.env` не трогать (примеры: `google_probe.py`, `link_probe.py`).
2. **Значения-лейблы стора** (Молния, Щелчок, Ксерокс…) не переводить — выводить через `useChip()`.
3. **Figma-иконки** имеют `preserveAspectRatio="none"` → только через `FigIcon` +
   `src/data/figma-icon-box.json` (регенерация: `npm run icons:box`).
4. **Верификация правок:** скриншот-тул виснет — проверять DOM-замерами через
   `javascript_tool` (`getBoundingClientRect`, `getComputedStyle`).
5. **Не коммитить** без явной просьбы.

**Грабли этого окружения (проверено на практике):**
- `requestAnimationFrame`, CSS-переходы, CSS-анимации и `ResizeObserver` в браузерном пане
  **не тикают**. Не ставить логику на rAF/RO — фокус в поле ника из-за этого не работал,
  а размер фото-карточек разъезжался. Мерить после `el.style.transitionProperty='none'`.
- **react-query держит опросы на паузе**: пан ложно рапортует офлайн, поэтому
  `refetchInterval` не работает и прогресс генерации вживую не «тикает» — статусы читать
  запросом к API. Из-за этого же `isError` не наступает — см. `queryDown()` в `ErrorState.tsx`.
- `scroll-behavior: smooth` ломает программную прокрутку в замерах — временно отключать.
- Два Tailwind-класса `shadow-*` конфликтуют: побеждает тот, что позже в собранном CSS.
  Динамические тени задавать инлайн-стилем.
- Флекс с `align-items: stretch` перебивает `aspect-ratio` у дочернего.
- React слушает `focusout`, а не `blur` — в тестах диспатчить `FocusEvent('focusout')`.
- `add_middleware` оборачивает уже собранный стек: `SessionMiddleware` регистрируется
  **после** `bind_workspace`, иначе `request.session` в нём не существует.
- `TestClient` без `with`/`__enter__` **не запускает startup** — миграции не применяются.
- `secrets.compare_digest` бросает `TypeError` на не-ASCII: сравнивать байты.

## 3. Что сделано (не переделывать)

**Персистентность.** Состояние переживает рестарт: воркспейсы, батчи, итерации, аналитика,
реестр аккаунтов и токены входа лежат в БД. `app/db.py` — два диалекта за одним интерфейсом:
**SQLite по умолчанию** (`backend/data/blast.db`, WAL) и **Postgres по `DATABASE_URL`**.
Миграции в `backend/db/migrations`, применяются на старте, отмечаются в `schema_migrations`.
Имя файла задаёт диалект (`002_app_state.sqlite.sql` / `.postgres.sql`); файл без суффикса
(`001_render_jobs.sql`) считается постгресовым и не переезжает — путь к нему зашит в
`docs/HANDOFF_render_node.md`.

Модель хранения — **документная** (JSON/JSONB на агрегат): приложение мутирует словари на
месте, в БД уезжает тот же словарь. Разложить по колонкам можно следующей миграцией,
интерфейс `persistence.py` не изменится. Запись — одним сбросом после мутирующего запроса
в middleware (`flush_user`), рендер-воркер сохраняется сам. Все записи обёрнуты `_guarded`:
падение БД пишется в stderr и не роняет уже выполненный запрос.

**Безопасность.** CSRF (double-submit: cookie `blast_csrf` + заголовок `X-CSRF-Token`,
фронт по коду `csrf_failed` обновляет токен и повторяет один раз), rate-limit по IP
(`/api/auth/*` 10/мин, загрузки 20/мин), проверка файлов **по содержимому** (магические
байты аудио и картинок), белый список расширений, санация имён, куки и CORS из окружения.
SameSite оставлен `lax` осознанно: при `strict` браузер не пришлёт куку на возврате с
домена TikTok после OAuth. Вынесен в `BLAST_COOKIE_SAMESITE`.

**Вход — два способа.**
- **Telegram**: личность = `chat_id`. Токены подтверждения в БД (`auth_tokens`), а не в
  памяти — раньше бот и веб в разных процессах не видели один токен, и `/start`
  приходилось жать по нескольку раз. Плюс: поллер стартует вместе с приложением,
  старая очередь апдейтов сбрасывается, голый `/start` без токена отвечает по-человечески,
  во всех ответах кнопка возврата на сайт.
- **Google** (OAuth code flow, `google_auth.py`): `client_secret` уходит только на сервер
  Google, `state` в сессии. Скоупы `openid email profile` — ревью в Google не нужно.
  `id_token` разбирается без проверки подписи осознанно: он приходит прямо от Google по TLS
  в ответ на серверный запрос с секретом.
- **Связывание**: в профиле кнопка «подключить Google» — почта пишется полем `googleEmail`
  на существующий аккаунт, вход по ней ведёт в ТОТ ЖЕ аккаунт. Второй ключ в реестре на
  того же юзера не заводится: на `user_id` стоит UNIQUE. Отвязать последний способ нельзя (409).
- **Гео**: из России Google не предлагаем (риск штрафов). Страна из заголовка прокси;
  нет заголовка — разрешаем. Проверка мягкая осознанно: без VPN сервис из России недоступен.

**Экран входа** — две равнозначные кнопки 528×76 со значками и подписями-выгодами.
ФИО спрашиваются только на регистрации и только для телеграм-пути (Google отдаёт их сам),
поэтому стоят под своей кнопкой и подписаны. Под кнопками — строка согласия со ссылками на
оферту и политику: акцепт происходит именно здесь, и ревью Google/TikTok проверяет её наличие.

**Вход и регистрация разведены.** `POST /api/auth/tg-start` принимает `mode`:
`login` выдаёт токен с purpose `login`, и такой токен аккаунт НЕ создаёт. Если человек нажал
«Войти», а аккаунта с этим Telegram нет, бот отвечает «зарегистрируйся» с кнопкой на
`/register`, а модалка на сайте показывает то же самое (`{verified:false, noAccount:true}`).
Раньше «Войти» молча заводило аккаунт и человек упирался в обязательный шаг ФИО — читалось
как сбой. `confirm_token` теперь возвращает `ok | expired | no_account`; дев-фолбэк без бота
вызывает его с `allow_create=True` и псевдо-chat_id `auth_store.DEV_CHAT_ID` (с `None`
ключ реестра получался `tg:None`, а поиск шёл по `tg:none` — подтверждение не срабатывало).

**Анти-фрод по TikTok** (`app/fraud_guard.py`, миграция `004_tiktok_guard.*`). Один аккаунт
TikTok даёт бесплатный лимит один раз: подключения пишутся в `tiktok_account_usage`, и если
аккаунт уже использовался другим аккаунтом сервиса — банится всё кольцо (замыкание по графу
«юзер ↔ open_id»). История не удаляется вместе с аккаунтом, иначе правило обходится удалением
аккаунта. Проверка стоит ДО сохранения подключения и fail-closed. Забаненному открыт только
`/api/auth/*`, остальное — 403 `account_banned`, фронт уводит на `/blocked` (экран объясняет
причину и даёт выйти). Дев-проверка: `POST /api/dev/ban`, снятие `?on=false`. Подробности —
`backend/README.md`.

**Юридические страницы.** `/legal/policy` и `/legal/offer` — настоящие документы (RU+EN) в
`frontend/src/data/legal-docs.ts`, рендерит `pages/LegalPage.tsx`. Открываются без входа.
Реквизиты, платёжный партнёр и условия оплаты взяты с лендинга
(`srv_blast/landing/{contacts,offer,privacy}.html`) и лежат прямо в коде (`LEGAL_ENTITY`,
`PAYMENT_PARTNER`): ИП Чернов Никита Романович, ИНН/ОГРНИП/адрес/телефон, приём платежей —
АО «Т-Банк», карты Visa/Mastercard/МИР и T-Pay, PCI DSS. Два источника с расходящимися
реквизитами — прямой путь к отказу модерации, поэтому значения совпадают с лендингом;
`VITE_LEGAL_*` остались как переопределение на случай смены реквизитов.
Состав тарифов в оферте — АКТУАЛЬНЫЙ веб-продукт (Blast 1 990/мес 100 роликов, Glow 7 990
400 роликов, Impulse 29 990 без лимита), а не старые пакеты бота из лендинга. Возврат
согласован с лендингом: до первой генерации — полностью, дальше — неиспользованный остаток.
Правило «один аккаунт TikTok — один лимит» и последствия бана описаны в разделе 9 оферты —
без этого блокировка не была бы обоснованной.

**Профиль** — TikTok остаётся крупной кнопкой (ключевое действие), Google и выход —
квадраты 60×60 только с иконкой. Google серый когда не подключён, фиолетовый когда подключён.
Иконки: `public/assets/icon-google.svg`, `icon-logout.svg` (перекрашены на `currentColor`).

**Состояния ошибок API** — `components/ui/ErrorState.tsx`: `ErrorState`, `InlineError`,
`QueryError`, хелпер `queryDown()`. Последний считает отказом ещё и «паузу» react-query
(`fetchStatus === 'paused'`) — без сети запрос не падает, а встаёт на паузу, и экран
навсегда застревал в скелетоне. Проверка `queryDown` идёт **до** `isLoading`.

**Аналитика итераций — по ПАРАМЕТРАМ, а не по связкам** (`analyze_iterations` в
`mock_store.py`, обвязка фронта в `lib/analysis.ts`). Каждое измерение (`background`,
`subtitles`, `fx`) разбирается отдельно: все ролики с Brat против остальных. Вердикты:
`signal` (лидер и отрыв), `no_difference` (данных хватило, разницы нет), `low_data`
(не хватает роликов), `blocked` (одно значение либо слиплось с другим измерением).
Формально в спеке было три вердикта — четвёртый (`no_difference`) добавлен осознанно:
«проверили, параметр не решает» это не «данных мало» и не «проверить нельзя».

Считается так: минимум 2 ролика на значение, порог отрыва 25%, плюс поправка
`confidence = отрыв / ошибку − sqrt(2·ln k)`, где ошибка нормирована на размер выборки, а
`k` — число значений. Сигналом считается только `отрыв ≥ 25% И confidence > 0`, поэтому
самое разнообразное измерение не выигрывает автоматически. Слипание определяется как
биекция значений по уже читаемым (≥2 ролика) значениям — это свойство раскладки, лечится
следующим батчем. Порог «10 роликов» убран: `videosNeeded` считается по каждому измерению.
В анализ идут только ОПУБЛИКОВАННЫЕ ролики.

UI: на `/app/stats` левая панель — ведущий параметр с барами «лидер vs остальные»
(в среднем на ролик), правая — следующая итерация, где «фиксируем» берётся из сигнала, а
«тестируем» из того, что проверить нельзя. Вердикты по всем измерениям — чипами в строке
итераций (отдельного блока нет: карточка ровно 505 по макету). Состояние сбора данных
отвечает на три вопроса (сколько выложено, сколько ждать в роликах и днях, что человек
получит) и отдельно ловит случай «все ролики на одних настройках» — там нужны не ролики,
а разнообразие. После выкладки последнего ролика батча кнопка ведёт в аналитику
(`/app/stats?project=<id>`), а не в список проектов.

**Метрики прохождения** (`analytics.flow_metrics`, ручка `/api/admin/analytics` → `flow`,
блок «Прохождение» в админке): отвал на экране ожидания (`waiting_opened` / `waiting_left`
с длительностью и признаком «дождался»), время на этапах визарда (`wizard_stage_time`,
отдельно медиана «Пула») и возвраты назад (`wizard_back` по этапам). Медианы, а не средние.

**DEV-флаги:** `?qaFail=/api/me` (или `all`) роняет ручки с 503 для проверки состояний
ошибки; `POST /api/dev/ban[?on=false]` — экран блокировки; `/api/tiktok/auth?reuse=1` —
мок-подключение с ОБЩИМ open_id (проверка анти-фрода); плюс прежние `?qaStage`, `?qaPost`,
`?plan`, `?state`, `/api/dev/*` (включая `?monthsAgo=` у `/api/dev/billing/{state}`).

**Закрыто за прошлые сессии:** ускорение выкладки батча (перенос настроек на батч, прогресс
«выложено N из M», хештег-подсказки, честное «сразу после публикации»), живой безлимит,
занятый экран ожидания, лимит отрывка заранее, отметка купленного тарифа, управление
проектами (переименование/архив/удаление), модалка проекта с треком и прослушиванием,
единый трёхшаговый мастер FX для всех хуков (`hookSteps` общий с фуллскрином), рабочая
кнопка бонуса, разведение продукта и подписки, скролл профиля.

**Правки визарда:** управление превью живёт В САМОМ плеере — плей по центру (запускает
выбранный отрывок своего трека, `useFragmentAudio` берёт файл по `track.localUrl`) и стрелки
44×44 по бокам; счётчик примеров вернулся в шапку компактной пилюлей «‹ N/M ›», как на
превью батча. Галочек выбора на примерах нет нигде (футаж, фото, субтитры) — только обводка.
Карусель «Комбинации»: кружки прижаты к краям пилюли, пилюля 140×42, подписи про листание
нет. Поле ручного ввода текста и так открыто сразу — кнопки «вставить из буфера» в коде нет
(замечание ревью относилось к более старой версии экрана).

**Статусы проекта считаются, а не хранятся** (`mock_store._display_status`): «Новый» —
генераций не было, «В процессе» — были, «Завершён» — ТОЛЬКО когда по другому проекту
генерация запускалась позже. Раньше статус ставил рендер-воркер по факту готовности батча,
и единственный проект в аккаунте становился «Завершён» сразу после первой генерации.
Считаем на чтении, чтобы правило чинило и уже сохранённые статусы.

**Мелочи интерфейса:** на строке проекта на дашборде — «N/M выложено» (в правой колонке
рядом с просмотрами: под названием всего 232px, и счётчик переносился на вторую строку).
В карточке «Все проекты» нет второй кнопки «Создать проект» — она дублировала hero.
В hero убрана надстрочная надпись «ПРОДОЛЖИТЬ». Плашки «Текущий проект» в хедере батчей
тоже нет: находясь внутри проекта, человек и так это знает.

**Имя из формы регистрации теперь доезжает до профиля** даже если аккаунт уже существовал
(`auth_store.confirm_token` обновляет name/surname из формы). Раньше форма молча
игнорировалась, и в приветствии навсегда оставалось имя из Telegram.

**Починенные баги:** ролики-сироты (бэк принимал `projectId` от клиента на веру), ник не
сохранялся (фокус через rAF), прогресс-бары лимитов, «Выложить» с дашборда вело в список
вместо выкладки, таймер после генерации, невидимая каретка, `compare_digest` на не-ASCII,
падение аналитики роняло запрос, отвязка Google не чистила воркспейс, дев-фолбэк входа без
бота не срабатывал из-за ключа `tg:None` (см. `DEV_CHAT_ID`), подключение TikTok не
сохранялось в БД (колбэк — GET, а сброс висел на мутирующих методах).

## 4. Что осталось

### 4.1 Действия владельца — без них деплой не поедет
1. **Вернуть ключи Google в `backend/.env`**: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
   `GOOGLE_REDIRECT_URI` — сейчас их там нет (TikTok и Telegram на месте), поэтому кнопка
   Google не показывается ни на входе, ни в профиле. В деве профиль показывает серый
   неактивный квадрат с подсказкой, в проде ненастроенный Google просто скрыт.
2. **Вычитать оферту и политику юристом.** Тексты написаны под нашу фактическую механику
   (что собираем, кому передаём, за что баним), но это не заключение юриста.
   Ключевое место — раздел 9 оферты: на нём держится законность бана за переиспользованный
   TikTok. Дата редакции — `LEGAL_UPDATED` в `data/legal-docs.ts`, менять при каждой правке.
3. **Бот верификации на отдельный токен** — правка `TELEGRAM_BOT_TOKEN` /
   `TELEGRAM_BOT_USERNAME` в `backend/.env`. Код динамический, но значения читаются при
   импорте модуля: после правки нужен рестарт бэка.
4. **Google Cloud Console** после деплоя: consent screen (ссылки на `/legal/*`), redirect URI
   боевого домена, перевод из Testing в Production.

### 4.2 Лендинг
В этом репозитории лендинга нет: его ассеты живут отдельно
(`s3.twcstorage.ru/.../landing/blast808/media/v1`, см. `backend/SPEC.md` §11). «Частичная
пересборка лендинга» из прошлого хендоффа сюда не относится — нужно решить, где он живёт,
и заводить задачу там. Ссылки на юр-страницы для футера лендинга: `<домен>/legal/policy`
и `<домен>/legal/offer`.

### 4.3 Не проверено вживую (ограничения пана, не кода)
- Движение градиента безлимита, текст ошибки «Сервер прилёг» (5xx), реакция фото-карточек
  на ресайз окна — с прошлой сессии.
- **Звук превью (плей в центре плеера)**: состояние кнопки, размер и центровка проверены,
  реальное воспроизведение в пане не слышно.
- **Rate-limit через Redis**: библиотеки `redis` в окружении нет, ветка не выполнялась —
  проверяется первым же запуском с `REDIS_URL` (без него код гарантированно идёт в память).
- **Бан реальным переиспользованием TikTok**: гонялся на мок-подключении (`?reuse=1`) и в
  изолированном прогоне; на живых ключах TikTok не проверялся.

### 4.4 Куда расти в аналитике (не срочно)
- Сейчас разбор берёт метрики из `video.metrics`, которые проставляет TikTok-синхронизация.
  Пока их нет, мок подставляет стабильное псевдо-значение — на проде эта ветка не включается,
  но и сигнала не будет, пока не поедет синхронизация статистики.
- Вердикт `blocked/entangled` сейчас показывает лидера пары, но не предлагает конкретную
  раскладку следующего батча. Следующий шаг — прямо предлагать «сделай 2×2», а не только
  называть измерение.

11. **Примеры результата и заполнение правой колонки на `/login`** — примеры живут на лендинге.

    в аналитике (решение по §4.4 прошлого хендоффа).

## 8. Стиль работы, который зашёл владельцу

- Правки приходят пачками со скриншотами — разбирать по пунктам, ничего не терять
- После каждой правки — **проверка вживую** (DOM-замеры) и короткий отчёт, что именно замерено
- Честно говорить, когда причина не в коде и когда что-то не проверено
- Не плодить сущности: если можно одной кнопкой/одним компонентом — делать так
- Искать НАСТОЯЩУЮ причину, а не симптом: почти каждый баг этой сессии оказался глубже,
  чем выглядел (ролики-сироты, четыре нажатия `/start`, пауза react-query)
- Работать автономно: задать блокирующие вопросы до старта, дальше идти по порядку
